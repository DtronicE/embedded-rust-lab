# 01 - Cargo for embedded targets

## What is different from desktop Rust?

| Desktop | Embedded |
|---------|----------|
| `std` (threads, files, heap) | `#![no_std]` - only `core` (and optional `alloc`) |
| `fn main()` called by the OS runtime | `#![no_main]` - *you* provide the entry via `#[entry]` |
| Panics print and unwind | A `panic_handler` crate decides (`panic-probe`: log + halt, `esp-backtrace`: print backtrace) |
| `cargo run` runs the binary | `cargo run` calls the **runner** (`probe-rs run`) to flash it to the MCU |

## Anatomy of a chip crate

```
stm32/
├── Cargo.toml              dependencies, profiles
├── rust-toolchain.toml     pin toolchain + targets
├── .cargo/config.toml      build.target, runner, rustflags (linker args), env
├── build.rs                copies memory.x to OUT_DIR
├── memory.x                where FLASH and RAM live
├── Embed.toml              cargo-embed configuration
└── src/main.rs
```

### Cargo.toml highlights
* `[workspace]` (empty) makes the crate its own root. Without it Cargo would look for a parent workspace.
* `cortex-m` feature `critical-section-single-core` supplies the `critical_section` implementation (disable interrupts) that HALs and `defmt-rtt` need.
* `[profile.*] debug = 2`: debug info lives only in the `.elf` on your PC. It is **not** flashed, so it costs nothing on the device but gives probe-rs source-level debugging.
* `opt-level = "s"` also for `dev`: unoptimised code can be 10x larger and may not even fit/timing-fail.
* `lto = "fat"`, `codegen-units = 1`: smallest, fastest code, slower compile.

### .cargo/config.toml
```toml
[build]  target = "thumbv7em-none-eabihf"        # cross-compile by default
[target.thumbv7em-none-eabihf]
runner   = "probe-rs run --chip STM32F411CEUx"   # `cargo run` = flash + run
rustflags = ["-C","link-arg=-Tlink.x", "-C","link-arg=-Tdefmt.x"]
```
`-Tlink.x` passes the linker script *generated by cortex-m-rt* (see doc 02).
`-Tdefmt.x` adds defmt's section for log strings.

### Features
HAL crates are selected by **chip feature**: `stm32f4xx-hal = { features = ["stm32f411"] }` picks the PAC, register layout and interrupt table. Wrong feature = wrong peripherals / pin AF numbers.

### Useful commands
```bash
cargo build --release
cargo size --release -- -A        # section sizes (.text/.rodata in flash, .data/.bss in RAM)
cargo objdump --release -- -d | less
cargo clippy --release
cargo tree                        # inspect dependency graph
cargo expand                      # see what #[entry] expands to (cargo install cargo-expand)
```

### Host-testable code
Pure logic (debouncing, pattern generators, protocol parsers) lives in a `shared/` crate marked
`#![cfg_attr(not(test), no_std)]`. You can run `cargo test` for it **on your PC** (it has no `.cargo/config.toml` forcing an embedded target). This is the best practice in embedded Rust: put logic in hardware-independent crates, keep `main.rs` as thin glue.
